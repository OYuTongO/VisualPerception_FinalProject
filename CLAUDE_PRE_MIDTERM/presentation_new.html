技术选型依据

相机LanXin Eagle Pro — 高帧率、低畸变、强弱光
视觉MediaPipe Tasks API（0.10.35+）
模型RandomForest — 速度快，无需 GPU
界面Pygame — 跨平台，帧级渲染控制

关键设计决策

  • MediaPipe 0.10+ 移除 mp.solutions API，迁移至 Tasks API + .task 模型文件
  • 坐标二次归一化到手部 BBox，消除位置和尺度干扰
  • 排除 J、Z（动态手势），仅识别 24 个静态字母
  • 摄像头帧在子线程采集，Pygame 主循环保持 30 FPS
Retrospective

难点复盘

坑 01 · API 断代
MediaPipe 0.10.35 彻底移除 mp.solutions API
网上 90% 教程代码直接 AttributeError，无法运行。需自行下载 hand_landmarker.task 模型文件，完全重构 HandLandmarker 初始化逻辑，迁移至 Tasks API。
✓ 解决：迁移至 Tasks API，项目长期可维护，适配最新版本
坑 02 · 特征不稳定
直接使用 MediaPipe 输出坐标导致同一手势在不同距离下差异大
MediaPipe 输出已归一化至图像尺寸 [0,1]，但仍受手在画面中的位置和距离影响。直接用此特征训练，模型对手离摄像头远/近极其敏感，泛化能力差。
✓ 解决：对 21 个关键点再做 BBox 相对归一化（x_norm = (x − x_min) / w），准确率从 ~92% 提升至 98.70%
坑 03 · 重复触发
保持同一手势不动时，游戏持续接收该字母，单词被快速"刷过"
原始实现中每帧均输出识别结果，用户无需切换手势即可连续输入同一字母，游戏逻辑完全失控，体验极差。
✓ 解决：引入 _last_confirmed 字段 + deque 缓冲，仅在字母切换时触发；收回手再伸出可重复输入
坑 04 · M / N 混淆
M 与 N 手型极为相似（3 指折叠 vs 4 指折叠），互相混淆
M（95.4%）和 N（94.4%）是全部 24 个字母中准确率最低的两个，属于固有的视觉歧义难点，即使增加样本量改善也有限。
✓ 缓解：单词库设计中规避高频 MN 连续组合；后续可针对性数据增强
Future Enhancement

后续深化改进方向

01
动态手势扩展（J & Z）
LanXin Eagle Pro 高帧率（≥60fps）为时序建模创造硬件条件，引入光流法轨迹建模或简单 LSTM（~15 帧序列），识别 J 形 / Z 形轨迹，补全全部 26 字母。
技术路径：连续帧关键点序列 → 光流 / LSTM → 轨迹分类
02
手势质量评分（超越对/错二分）
以标准 ASL 关键点坐标为模板，计算用户手势与模板的余弦相似度或关节角度偏差，输出百分制质量分，如"你的 A 大拇指弯度不足，得 83 分"。
技术路径：关键点模板匹配 → 余弦相似度 / 角度误差
03
个性化弱点追踪 + 自适应出题
记录每个用户每个字母的历史错误率，生成 24 格字母热图；测试模式根据热图加权采样，高错误率字母出现频率更高，类似 Anki 间隔重复算法。
技术路径：错误率热图 → 加权随机采样 → 个性化出题
04
增量学习 · 适应个体手型差异
游戏开始前加入 5 分钟校准环节，每个字母比划 3~5 次，新样本加入训练集做增量微调，解决不同用户手的大小/比例/习惯差异导致的识别偏差。
技术路径：sklearn warm_start=True，RandomForest 增量添加树
05
双手识别 + 连续字母流输入（Freeplay 升级）
MediaPipe 支持 num_hands=2，可同时检测双手。在 Freeplay 模式中实现连续字母流自动分词（基于手势停顿时间窗口），让自由模式从"展示工具"升级为真正的"手语输入法"。
技术路径：双手并行 Recognizer → 停顿检测 → 自动分词
