**标题：** 技术选型：为什么是这套组合？

**逻辑结构：** 先给出整体流程图，再逐层说明选型理由

### 端到端流程（横向五步）
```
[LanXin Eagle Pro 工业相机]
        ↓ 高帧率 RAW 视频流
[OpenCV 采集线程（子线程，不阻塞主循环）]

        ↓ 概率向量 (24 类)
[3 帧平滑缓冲 + 置信度门控 (threshold=0.6)]
        ↓ 确认字母
[Pygame 游戏逻辑层]
```

| 层级 | 选用方案 | 备选方案 | 选用理由 |
|------|---------|---------|---------|
| 相机 | LanXin Eagle Pro | 笔记本内置摄像头 | 更高帧率、低畸变、强弱光适应 |

| 界面 | Pygame | Tkinter, Qt | 跨平台，帧级渲染控制，精确计时 |
| 数据集 | Kaggle ASL Alphabet (87,000 张) | 自采数据 | 覆盖广、光照多样、免标注成本 |

## Slide 4 — 核心技术：视觉管线深解

**标题：** 视觉管线：从像素到字母

**逻辑结构：** 三个关键技术细节，每个都说清楚"是什么 → 为什么要这样做"

### 关键点一：MediaPipe Tasks API 升级
- MediaPipe 0.10.35 **移除了** `mp.solutions.hands` API
- 必须使用新的 Tasks API + `.task` 模型文件（`hand_landmarker.task`）
- 代码变化：
  ```python
  # 旧 API（已弃用）
  mp.solutions.hands.Hands()
  # 新 Tasks API
  mp_vision.HandLandmarker.create_from_options(options)
  ```
- 影响：项目适配了最新 MediaPipe，确保长期可维护性

### 关键点二：边界框二次归一化
- MediaPipe 输出坐标已归一化至图像尺寸 [0, 1]，但仍受**手在画面中的位置和距离**影响
- 我们在此基础上再做一次相对手部 Bounding Box 的归一化：
  ```python
  x_norm = (lm.x - x_min) / (x_max - x_min)
  y_norm = (lm.y - y_min) / (y_max - y_min)
  ```
- 效果：消除平移不变性和尺度不变性，手离摄像头远近不影响识别

### 关键点三：3 帧平滑 + 一次触发机制
- 使用 `collections.deque(maxlen=3)` 作为滑动窗口缓冲
- 只有**连续 3 帧预测一致**且与上一次确认字母不同时才触发输出
- 用户收回手再伸出可重复输入同一字母（重置 `_last_confirmed`）
- 解决问题：避免同一手势在游戏中被重复计入，防止吉祥物状态抖动

## Slide 5 — 数据与模型成果

**标题：** 数据管线 + 模型训练结果

**逻辑结构：** 数据规模 → 训练策略 → 量化结果 → 弱点分析

### 数据规模
| 指标 | 数值 |
|------|------|
| 原始图片总数 | ~87,000 张（Kaggle ASL Alphabet） |
| 成功提取关键点样本 | **57,339 条** |
| 跳过（未检测到手） | ~29,000 张 |
| 类别数 | **24 个字母**（排除 J、Z） |
| 特征维度 | 42（21 点 × x、y 各 1） |
| 数据集划分 | 训练集 80% / 测试集 20%（stratified） |

### 训练策略
- 优先使用 `RandomForestClassifier(n_estimators=100, random_state=42, n_jobs=-1)`
- 若准确率 < 90% 则自动切换至 `MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=500)`
- 实际结果：RandomForest 直接达标，无需切换

### 量化结果
| 模型 | 测试集准确率 |
|------|------------|
| RandomForestClassifier | **98.70%** ✅ |
| MLPClassifier（对照） | ~97% |

### 弱项字母分析（最值得关注）
| 字母 | Precision/Recall | 原因 |
|------|-----------------|------|
| **N** | 94.4% | 手型与 M 极为相似（3 指折叠 vs 4 指折叠） |
| **M** | 95.4% | 同上，M/N 互相混淆 |
| 其余 22 个字母 | ≥ 97% | 正常水平 |

- **应对策略：** 单词库设计中规避高频 MN 连续组合；后期可考虑针对 M/N 采集更多样本做数据增强

## Slide 6 — 系统架构

**标题：** 模块化架构：从采集到游戏

**逻辑结构：** 三层架构（输入层 → 视觉核心层 → 游戏层），重点说明各模块职责和接口

### 完整架构图（三层）

```
┌──────────────────────────────────────────────────────┐
│                     输入层                            │
│  LanXin Eagle Pro → OpenCV VideoCapture（子线程）     │
└────────────────────────┬─────────────────────────────┘
                         ↓ numpy BGR frame
┌──────────────────────────────────────────────────────┐
│                   视觉核心层                           │
│  src/recognizer.py — Recognizer 类                   │
│  ├─ MediaPipe HandLandmarker（手部检测）               │
│  ├─ _normalize()（边界框归一化 → 42-dim vector）       │
│  ├─ RandomForest.predict_proba()（分类推理）           │
│  ├─ deque(maxlen=3) 平滑缓冲                          │
│  └─ get_landmarks() → 骨架坐标供 Pygame 绘制          │
│                                                      │
│  对外接口：                                           │
│    letter, confidence = rec.predict(frame)           │
│    landmarks = rec.get_landmarks()                   │
└────────────────────────┬─────────────────────────────┘
                         ↓ (letter, conf, landmarks)
┌──────────────────────────────────────────────────────┐
│                     游戏层                            │
│  src/game/main.py — SceneManager（30 FPS 主循环）     │
│  ├─ menu.py         主菜单，场景路由                   │
│  ├─ learn_mode.py   学习模式（Phase 6）               │
│  ├─ test_mode.py    测试模式（Phase 7）               │
│  ├─ freeplay_mode.py 自由模式（Phase 8）              │
│  ├─ mascot.py       吉祥物三态（IDLE/CORRECT/WRONG）  │
│  └─ word_list.py    三档难度单词库                    │
│                                                      │
│  src/utils/                                          │
│  ├─ draw.py         Pygame 绘图工具函数               │
│  └─ score.py        计分 + Top 5 排行榜持久化         │
└──────────────────────────────────────────────────────┘
```

### 关键设计原则
- **子线程采集**：摄像头帧在独立线程中 capture，通过共享队列传给主循环，确保 Pygame 30FPS 不被 I/O 阻塞
- **场景管理器**：`SceneManager` 统一管理 `MENU → LEARN / TEST / FREEPLAY` 切换，ESC 返回上一场景
- **Recognizer 作为独立模块**：游戏层只调用接口，视觉层与游戏层完全解耦，便于后续替换模型

**主视觉建议：** 三层架构图用不同色块区分（蓝/绿/紫），文件名用等宽字体，层间用粗箭头连接

## Slide 7 — 游戏设计：三大模式

**标题：** 游戏设计：三种模式构建完整学习闭环

**逻辑结构：** 三个模式卡片并排，每个说明目标用户场景 + 核心交互逻辑 + 技术实现要点

### 学习模式 Learn Mode（`src/game/learn_mode.py`）
**定位：** 零基础入门，无时间压力，引导式练习

- 从 Easy 词库随机取词（如 CAT / SUN / DOG）
- 屏幕顶部显示完整目标单词，**高亮当前目标字母**（如 `C̲AT`）
- 左侧：该字母的 ASL 参考图示；右侧：摄像头画面 + 手部骨架叠加
- 中央：吉祥物小人实时反馈
  - 无手 → `IDLE`（轻微呼吸动画）
  - 字母匹配 → `CORRECT`（停留 1.5 秒后自动推进）
  - 字母不匹配 → `WRONG`
- 单词完成后播放完成动画，随机切换下一个词
- 支持 `→` 跳过当前字母，`ESC` 返回菜单

### 测试模式 Test Mode（`src/game/test_mode.py`）
**定位：** 学习成果检验，计时计分，有压迫感

- 随机从 Easy + Medium 词库出 5 个单词
- 每字母限时 **10 秒**，超时自动记为错误跳过
- 计分规则：答对字母 **+10 分**，完整拼对单词额外 **+20 分**
- 游戏结束页显示：总分 / 正确字母数 / 总用时 / **最弱字母（错误次数最多）**
- 本地排行榜：`score.json` 持久化 Top 5 历史最高分

### 自由模式 Freeplay（`src/game/freeplay_mode.py`）
**定位：** 自由练习 / 课堂演示场景

- 全屏摄像头画面作为背景，手部骨架实时叠加
- 左上角大字号显示当前识别字母 + 置信度进度条
- 最近 5 个字母横向滚动历史记录
- 右下角迷你吉祥物跟随识别结果切换状态

### 单词库设计
```python
WORD_LIST = {
    "easy":   ["HI", "BYE", "CAT", "DOG", "SUN", "HAT", "BAG", "CUP", "RUN", "FUN"],
    "medium": ["HELLO", "THANK", "WATER", "APPLE", "BOOKS", "MOUSE", "HAPPY", "DANCE"],
    "hard":   ["FRIEND", "SCHOOL", "FINGER", "PYTHON", "CAMERA", "VISUAL", "SIGNAL"],
}
# 规则：全部排除 J、Z（动态手势，当前模型不支持）
```

## Slide 8 — 吉祥物设计 + 硬件升级

**标题：** 细节决定体验：吉祥物 × 工业相机

**逻辑结构：** 两个独立亮点，各自说清楚设计逻辑

### 亮点一：吉祥物小人（`src/game/mascot.py`）

**核心思路：** 用纯 Pygame 基本图形（圆形 + 线条）绘制，零外部资源依赖，三种状态通过不同关节坐标定义

| 状态 | 触发条件 | 视觉表现 |
|------|---------|---------|
| `IDLE` | 无手检测 / 等待输入 | 站立，手臂自然下垂，轻微呼吸上下浮动动画 |
| `CORRECT` | 连续 3 帧匹配目标字母 | 双臂高举欢呼，绿色光晕扩散，眼睛变成弧线（开心） |
| `WRONG` | 置信度达标但字母错误 | 双臂摊开摇头，头部轻微倾斜，红色抖动效果 |

**技术实现：**
- 三种状态各自定义关节坐标字典（如 `CORRECT_POSE = { "left_arm": (x1, y1, x2, y2), ... }`）
- 状态切换时使用**线性插值（Lerp）**过渡，约 0.3 秒完成姿态变换
- 对外接口：`mascot.set_state("IDLE" | "CORRECT" | "WRONG")`
- 呼吸动画：`IDLE` 状态下头部/身体 y 坐标按 `sin(time)` 微幅抖动（振幅约 2px）

**设计价值：** 将"识别结果"从冷冰冰的文字变成有情绪的角色，显著提升交互感和用户留存动机

---

### 亮点二：硬件升级 — LanXin Eagle Pro 工业相机

**替换理由对比：**

| 指标 | 笔记本内置摄像头 | LanXin Eagle Pro |
|------|--------------|-----------------|
| 帧率 | 30fps | ≥ 60fps（可配置） |
| 分辨率 | 720p | 1080p+ |
| 弱光表现 | 噪声明显 | 大光圈，低噪 |
| 畸变 | 广角畸变较大 | 低畸变镜头 |
| 对手部检测的影响 | 快速手势易模糊 | 快速动作边缘清晰 |

**工程影响：**
- 更高帧率为后期动态手势识别（J、Z）打下硬件基础
- 更清晰的关键点定位精度提升，尤其有利于 M/N 这类细微差异的手型
- OpenCV 只需修改 `cv2.VideoCapture(device_id)` 中的设备索引，无需改动其他代码

## Slide 10 — 难点复盘 + 深化改进路径

**标题：** 难点复盘 × 后续深化方向

**逻辑结构：** 先复盘已踩过的坑（证明工程落地能力），再展望有逻辑的深化路径（证明学术潜力）

### 难点复盘（已解决）

**坑 1：MediaPipe API 断代**
- 问题：MediaPipe 0.10.35 彻底移除 `mp.solutions` API，网上 90% 教程代码直接报错
- 解决：迁移至 Tasks API，自行下载 `hand_landmarker.task` 模型文件，重构 `HandLandmarker` 初始化逻辑
- 收获：项目使用最新 API，长期可维护性更好

**坑 2：关键点坐标的平移/尺度问题**
- 问题：直接使用 MediaPipe 输出的图像归一化坐标，模型对"手离摄像头远/近"非常敏感，同一手势在不同距离下特征向量差异大
- 解决：对 21 个关键点做边界框相对归一化（减去 x_min/y_min，除以 bbox 宽高）
- 收获：42 维特征向量对平移和尺度完全不变，准确率从约 92% 提升至 98.70%

**坑 3：同一手势被重复触发**
- 问题：用户保持同一手势不动，游戏会持续接收该字母，导致单词被快速"刷过"
- 解决：引入 `_last_confirmed` 字段，只有字母切换时才触发；用户收回手再伸出以重置状态
- 收获：交互逻辑更自然，符合用户直觉

### 后续深化方向（Proposal 展望）

**方向 1：动态手势扩展（J & Z）**
- 当前排除 J（J 形轨迹）和 Z（Z 形轨迹），因其为动态手势，单帧特征无法区分
- 规划：利用 LanXin Eagle Pro 的高帧率（≥60fps），提取连续帧关键点序列
- 技术路径：光流法轨迹建模 **或** 简单 LSTM（序列长度 ~15 帧）对轨迹方向分类
- 目标：补全全部 26 个字母

**方向 2：手势质量评分（超越对/错二分）**
- 当前只输出"识别到 / 未识别到"，反馈粒度粗
- 规划：以标准 ASL 关键点坐标为模板，计算用户手势与模板的**余弦相似度**或**关节角度偏差**
- 输出：百分制质量分（如"你的 A 还差一点大拇指弯度，得 83 分"）
- 价值：把反馈从"对/错"升级为"好/更好/标准"，显著提升学习效果

**方向 3：个性化弱点追踪 + 自适应出题**
- 当前 `score.py` 仅做排行榜
- 规划：记录每个用户每个字母的历史错误率，生成**字母热图**（A-X 的 24 格热力图）
- 测试模式根据热图**加权随机采样**，高错误率字母出现概率更高（类似 Anki 间隔重复算法）
- 价值：让每个用户都有个性化的弱点攻克路径

**方向 4：增量学习适应个体手型差异**
- 问题：不同人手的大小、比例、习惯姿势不同，通用模型对部分用户准确率会下降
- 规划：在游戏开始前加入 5 分钟的**用户校准环节**（每个字母比划 3~5 次），将新样本加入训练集做增量微调
- 技术：`sklearn` 的 `warm_start=True` 支持 RandomForest 增量添加树

**方向 5：双手识别与连续字母流输入**
- MediaPipe 支持 `num_hands=2`，可同时检测双手
- 规划：在 Freeplay 模式中实现**连续字母流自动分词**（基于手势停顿时间窗口），让自由模式从"展示工具"变成真正的"手语输入法"
